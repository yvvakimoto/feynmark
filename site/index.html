Write the physics, not the coordinates

A code block holds diagram and equation blocks. External legs are pinned to the borders; internal vertices are placed by minimising Σ tension·|Δp|² — the feynMF algorithm, solved exactly. The same input always produces the same diagram. 

diagram tree {
  in  e1: $e^-$,  e2: $e^+$
  out m1: $\mu^-$, m2: $\mu^+$
  e1 -- [fermion] a -- [fermion] e2
  a  -- [photon, momentum=$q$] b
  m2 -- [fermion] b -- [fermion] m1
}
diagram penguin {
  in  b: $b$
  out s: $s$, ph: $\gamma$
  b  -- [fermion] v1 -- [fermion, label'=$t$] v3
  v3 -- [fermion, label'=$t$] v2 -- [fermion] s
  v1 -- [boson, bend left=70, label=$W$, tension=0.35] v2
  v3 -- [photon] ph
}

Diagrams as terms inside equations

Reference a diagram with @name from an equation block and it is typeset as a term, vertically centred on the math axis. Diagrams used this way are re-laid-out compactly, so stroke weights and labels stay full size instead of being shrunk along with the whole figure. 

diagram lo {
  in  e1: $e^-$, e2: $e^+$
  out m1: $\mu^-$, m2: $\mu^+$
  e1 -- [fermion] a -- [fermion] e2
  a -- [photon] b
  m2 -- [fermion] b -- [fermion] m1
}
equation amp {
  i\mathcal{M} = @lo \;+\; \mathcal{O}(\alpha^2)
}

Why feynmark

Zero runtime dependencies

One standalone script tag. KaTeX is an optional peer dependency — without it, labels degrade to plain italic text.

Deterministic layout

feynMF-style tension minimisation, solved exactly. No physics simulation, no random seeds, no jitter between runs.

Markdown-native

Scans for pre > code.language-feynman — exactly what a markdown renderer emits for a feynman fenced block.

Publication-quality SVG

Sine photons, coiled gluons, braided gravitons, momentum arrows, blobs and counterterm crosses, all as clean vector output.

Escape hatches

When the automatic layout is not what you meant: tension=, bend left/right, half left, or explicit at (x, y).

Works everywhere

ESM, CJS and IIFE builds with TypeScript types. render() returns SVG strings without touching the DOM, so server-side rendering works too.

Quick start

Drop in the script tags and write a feynman code block. feynmark renders every match on DOMContentLoaded.

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/katex@0.16/dist/katex.min.css">
<script defer src="https://cdn.jsdelivr.net/npm/katex@0.16/dist/katex.min.js"></script>
<script defer src="https://cdn.jsdelivr.net/gh/yvvakimoto/feynmark@v0.1.0/cdn/feynmark.min.js"></script>

<pre><code class="language-feynman">
diagram {
  in  q: $q$
  out g: $g$, q2: $q$
  q -- [fermion] v -- [fermion] q2
  v -- [gluon] g
}
</code></pre>

feynmark is served by jsDelivr straight from the tagged commit, so pin a tag (@v0.1.0) in production; @0.1 follows the newest patch release. It is not on npm yet — for a bundler, clone the repo and npm run build. The README has the full API.

Syntax at a glance

Propagator styles

fermionsolid line, mid arrow
anti fermionsolid line, reversed arrow
plainsolid line, no arrow
scalardashed
charged scalardashed, with arrow
ghostdotted
photon / bosonsine wave
gluoncoil
doubledouble line
majoranadouble line, opposing arrows
gravitonbraided double wave

Edge attributes

label=$..$label left of the travel direction (label' = right)
momentum=$..$momentum arrow (mom dir=back reverses)
arrow=…forward / back / none / both
bend left=degcircular arc, default 30°
half left90° arc — two of them make a loop
loop=uptadpole self-loop on a -- a
tension=nlayout spring weight (lower = longer)
color=…, width=nstroke overrides

Vertices & diagram options

dot, blob, crossvertex marks (blob=shade, cross = counterterm ⊗)
at (x, y)explicit placement, y-up
direction=…right / left / down / up
baseline=vanchor line used when embedded in an equation
